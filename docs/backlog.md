# Workbar 后续开发计划（Backlog）

> 状态：部分已实现（每条标题后有标注）；未实现的条目保留已讨论清楚的设计结论，避免以后重复讨论。
> 每条都标了优先级和「不做」的边界。

## 1. 正计时 / 倒计时（✅ 已实现，2026-10-22）

**问题**：原来只有倒计时（按 `est_min` 算进度）。有些任务没有明确时长，或者本来就是「做了多久」的正计时需求。

**最终实现**

- Task 增加可选字段 `timer: "down" | "up"`；省略时推断：有 `est_min` 或起止时间窗 → `down`；都没有 → `up`。
- 倒计时（down）：圆环 = 已用 / 预估；文案 `已用 01:25 / 预计 30 分钟`；超时变琥珀色。
- 正计时（up）：**圆环每小时转一圈**（`spent % 3600`）；文案只显示 `01:25`，不显示预估；没有"超时"概念。
- 收起态细线：
  - down：从两端向中间收缩；
  - up：**固定宽度**（12%）+ 运行时亮度呼吸；暂停时静态偏暗。
- MCP：`plan_day` / `add_tasks` / `update_task` 都支持 `timer`；工具返回里正计时任务使用 `timer: "up"`。
- 没做（保留为不做的边界）：番茄周期、通知音、暂停历史、自定义提醒。

## 2. 多任务同时计时 + 单行多任务单元（✅ 已实现，2026-10-21）

> 实现时设计有调整：原计划的「chip + 小绿点 / ◷」被去掉，改为**所有任务都用同一套展开单元**（单行，不增高）。下面是最终形态。
>
> 一行最多 3 个单元（宽度限制）：统一优先保留已开始的任务，再补充待开始任务，选中后按开始时间和 id 排列；多出来的折叠成右侧 `+N`（悬停显示列表）。

**数据与计时规则**

- 数据层允许任意多个任务 `running: true`。
- ticker 给**所有** running 任务累加 `spent_sec`（小数秒跨 tick 累加，避免半秒 delta 被 floor 丢掉）。
- 每项任务独立维护运行、暂停和完成状态，没有“当前任务”或首项的额外待遇。
- 点圆环只暂停/开始这一项，点对勾只完成这一项；其他任务保持自己的状态。

**展开态（单行，最多 3 个单元）**

- 每个单元 = 圆环（身份色）+ 标题 + 时间 + ✓，圆环颜色与收起态分段一一对应。
- **未开始**：只显示 `21:19 开始`（不显示已用时间、不画进度弧）；临近时右侧提示分档：`不到 1 小时` / `不到 30 分钟` / `不到 15 分钟` / `不到 10 分钟` / `不到 5 分钟`。
- **运行中**：`已用 / 时长`（如 `15:51 / 10分钟`）；超时用琥珀色圆环和状态点表示，不再附加超时量文字。
- **暂停**：显示 `已用 / 时长`；圆环变暗、播放图标保持清晰，暂停状态会持久保存。
- 超过 3 个任务时折叠为 `+N`，悬停显示被折叠的任务。

**收起态分段显示**

| 已开始且未完成的任务数（含暂停） | 显示 |
|---|---|
| 0（全部完成 / 没计划 / 尚未开始） | 什么都不显示 |
| 1 | 单线 |
| 2–3 | 等宽分段，**无缝隙**，靠颜色 + 亮度区分 |
| 4 及以上 | 只显示 3 段 |

- 同样状态使用同样亮度：运行段正常显示，暂停段变暗；颜色与展开时对应的任务保持一致。
- 分段颜色（按序使用，避开语义色）：

  | 序号 | 颜色 | 渐变 |
  |---|---|---|
  | 1 | 靛蓝紫 | `#6E7BFF → #A57BFF` |
  | 2 | 青柠 | `#22D3EE → #2DD4BF` |
  | 3 | 玫红 | `#FB7185 → #F472B6` |

- 正计时运行时呼吸，暂停后停止呼吸并变暗；倒计时按剩余比例收缩，暂停后变暗。


## 3. 任务来源链接（P2，方案待细化）

**目标**：AI 把任务加进 Workbar 之后，点一下能打开对应的「工作现场」——项目文件夹、文件、issue 页面，或者（如果客户端支持）当时的对话。

**设计草案**

- Task 增加可选 `link`（URL / 路径）和 `source`（哪个客户端加进来的）。
- MCP：`plan_day` / `add_tasks` / `update_task` 增加 `link`；工具描述里要求 AI 只在知道确切位置时填写。
- 交互：展开态里，有 `link` 的任务标题后显示一个 `↗` 图标；点击打开；hover 显示来源。
- 安全性：
  - 只允许白名单 scheme：`http` / `https` / `file` / `vscode` / `cursor` 等编辑器；
  - `file` 链接默认只打开所在文件夹并选中文件（不直接执行）；
  - 未知 scheme 一律忽略并记日志；
  - 绝不允许执行任意命令。
- 已知限制：「回到原来那个 AI 对话」取决于客户端是否暴露可寻址 URL，无法保证。

**待定**：点标题打开还是单独图标；默认打开偏好（浏览器 / 文件夹）；是否展示 source。

## 6. AI 工作会话（✅ 已实现，2026-10-22）

**目标**：用户给 AI 派一件活，AI 就把这件活挂到 Workbar 上开一个**立刻计时**的正计时，干完标记完成。

**最终实现**

- 两个 MCP 工具：
  - `workbar_start_work({title})`：新建一个 `timer: "up"`、`running: true`、带 `source`（客户端名）的任务，保留其他任务的原有状态。
  - `workbar_finish_work({id?})`：只停表并完成指定任务（保留记录）；仅当本客户端只有一个未完成会话时才可省略 id，有多个候选则要求明确 id，不按任务位置或创建先后选择，也不结束其他客户端的会话。
- 提示词通过两条通道下发（全部在 Workbar 侧，不写任何客户端规则文件）：
  1. MCP `instructions` 第 7 条（会被注入的客户端：Claude Code、DSH）；
  2. `workbar_start_work` / `workbar_finish_work` 的工具描述（`tools/list`，必达通道）；
  - 2026-10-26：取消工具返回末尾的重复流程提醒，写入结果只包含本次涉及的任务。
- 已知客户端差异：**CodeBuddy 不注入 MCP instructions，且默认把 MCP 工具当延迟工具**（ToolSearch），所以它的模型不会主动调用；给它的 server 配置加 `"alwaysLoad": true` 可让工具直接加载，但仍可能需要用户明说一句才触发。README 已记录。

**补充决定（2026-10-22）**：不再指望各客户端的 MCP instructions 都能生效。
最终采用**用户级全局上下文**方案：README 收录一段固定的「Workbar 任务记录」文本，
用户（或让 AI 自己）把它加到客户端的全局上下文（`AGENTS.md` / 全局记忆 / `CODEBUDDY.md` 等）。
MCP 侧的 instructions、工具描述、返回提醒全部保留，两者不冲突。

**不做**：由 Workbar 安装器去改各个 Harness 的配置文件或写用户规则；只提供可复制的上下文文本，用户自助。
