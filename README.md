## 能力速览

- **正计时**：无需预设时长，记录每项工作投入的时间。
- **倒计时**：设定预计时长，直观掌握剩余时间与超时状态。
- **通过 MCP 交给 AI 操作**：接入后，AI 可以创建、查看、修改、排序和删除任务，也可以开始、暂停、继续计时或标记完成。通过对话，就能管理 WorkBar 中的任务与计时。

## 快速开始

当前支持 Windows x64。

<p>
  <a href="https://github.com/Obsucre777/WorkBar/releases/latest/download/WorkBar-setup-win64.exe">
    <img src="docs/assets/download-windows.svg" alt="下载 Windows 版" width="252" height="56" />
  </a>
</p>

1. **安装并启动**：运行安装包，完成安装后打开 WorkBar。安装器会自动将 `workbar-mcp` 加入当前用户的 PATH。
2. **接入 MCP**：把下面的提示词发给你的 AI 客户端，让它替你完成接入。完成后，新建对话开始使用。

   ```text
   请帮我把本机已安装的 WorkBar 接入当前 AI 客户端的 MCP。

   WorkBar 的接入信息：

   - 服务名称：`workbar`
   - 传输方式：`stdio`
   - 启动命令：`workbar-mcp`，安装时已加入 PATH
   - 无需启动参数、API Key 或远程地址

   请先检查启动命令是否可用，再确认当前客户端支持的 MCP 接入方式，尽量直接完成配置。
   优先使用用户级配置，保留已有的其他 MCP 服务；
   如果 WorkBar 已接入，检查现有配置即可，避免重复添加。

   配置后，请验证连接和工具是否可用，验证时仅查询信息，不要改动我的任务。
   如果需要授权、重启客户端或新建会话，请明确告诉我下一步该做什么。
   若无法自动完成，请给出最少的手动操作步骤。
   ```

3. **配置全局提示词**：将下方规则添加到 AI 客户端的全局提示词或全局规则中，让 AI 知道哪些任务需要记录，以及何时开始、更新和结束记录。

   <details>
   <summary>展开并复制全局提示词</summary>

   ```text
   ## Workbar 任务记录

   Workbar 用于展示 AI 正在推进的任务，以及用户主动要求记录的待办。
   只记录有跟踪价值的工作，不需要同步每次对话或操作。

   ### 何时记录

   以下情况适合记录：

   - **用户交付了明确的执行任务**：例如实现功能、修复问题、修改文件、撰写文档，
     或开展有明确目标的调研、分析、规划。
   - **用户主动要求记录任务**：例如“帮我加个待办”“把这几件事记下来”。
     即使暂时不执行，也可以添加。

   判断时，结合用户意图和上下文：这是否是一项需要推进、有明确目标或交付结果的独立工作，
   记录后是否有助于用户了解进度？

   以下情况通常不记录：

   - 寒暄、闲聊、感谢、需求澄清。
   - 简单问答、概念解释、随手查询、简短建议。
   - 对已有结果的补充说明或进度询问。
   - 完成任务过程中的内部步骤，例如读文件、搜索、运行命令、验证结果。
     这些操作归属于原任务，不单独建记录。

   不要仅因为使用了工具、执行了命令，或回复内容较长，就创建任务。
   不确定是否需要记录时，默认不记录，无需为此询问用户。

   ### 如何记录

   **执行任务**

   确定需要记录后，在开始实质工作前调用 `workbar_start_work`，
   可以与第一个其他工具调用同时发出。

   - `title` 使用用户的语言，简洁概括任务目标，不写成某个内部步骤。
   - 可用 `note` 补充必要背景。
   - 一项任务通常只创建一条记录，不随执行步骤拆分。

   **用户主动添加待办**

   用户明确要求添加任务或待办时，使用 `workbar_add_tasks`。
   按用户表达的事项添加，不把自己的执行计划自动转成待办，
   也不要把“添加待办”理解为“立即执行”。

   ### 状态更新

   对已经开始记录的任务，在完成、失败、确认无法继续或被用户取消时，
   调用 `workbar_finish_work`，如实说明结果，再给出最终答复。

   - 任务跨多轮继续，或暂时等待用户补充信息时，沿用原记录，不重复开始，也不提前标记完成。
   - 用户询问进度或补充要求时，继续归入原任务。
   - 已结束的任务再次需要实际执行时，可以用相同标题重新开始；仅解释已有结果时不必重新记录。
   - 用户切换到新的执行任务时，开始新记录；上一项尚未完成的，应如实说明其状态，避免误报完成。

   ### 异常处理

   - 工具只显示名称、没有参数定义时，先加载再调用。
   - 工具确实未连接或调用报错时，静默跳过，不阻塞工作，不用其他工具或文件替代；
     同一对话中确认不可用后，不再反复尝试。
   - 除非用户询问，不在回复中提及记录或计时操作。
   - 用户明确要求不使用 Workbar 时，停止记录。
   ```

   </details>

4. **安排第一项任务**：跟 AI 说：“帮我把写项目文档加入 WorkBar，预计 30 分钟。”任务会同步出现在桌面顶部。
